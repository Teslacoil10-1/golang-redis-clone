# Security Policy


## Reporting a Vulnerability

**Please do not open a public GitHub issue for security vulnerabilities.** Publicly disclosing a flaw before a patch is ready puts the project at risk.

Instead, please report vulnerabilities using one of the following secure methods:

### Method 1: GitHub Private Vulnerability Reporting (Preferred)
If enabled on this repository, please submit your report privately through GitHub:
1. Navigate to the main page of the repository.
2. Click the **Security** tab.
3. Click **Reporting a vulnerability** on the left sidebar.
4. Click **Start security advisory** and fill out the details.

### Method 2: Secure Email
If private reporting is unavailable, please email your report to **nrossiw@gmail.com**. 

## What to Include in the Report

To help us triage and fix the issue quickly, please include:
* A clear description of the vulnerability and its potential impact.
* The specific component, endpoint, or package affected.
* Step-by-step instructions to reproduce the behavior (including code snippets or payloads).
* Any potential mitigation steps or fixes you suggest.

## Our Response Process

* **Acknowledgement:** We will acknowledge receipt of your report within **48 hours**.
* **Triage & Patching:** If verified, we will work on a fix. We aim to release a patch within **30 to 90 days**, depending on complexity.
* **Credit:** We will gladly credit you in our security advisories and release notes once the vulnerability is resolved, unless you prefer to remain anonymous.
